When completing/delivering work, ASK Issam whether he wants a coding-level
explanation: WHAT changed, WHERE (files/functions), and a BRIEF why.

**Why:** he wants the option to understand the implementation, not just the
user-facing outcome — but only when he asks for it (don't dump code detail every
time by default).

**How to apply:** end a completed deliverable with a short offer like "Want the
code-level breakdown (what/where/why)?" Keep the default summary product-facing;
give the file/function-level detail only if he says yes.
